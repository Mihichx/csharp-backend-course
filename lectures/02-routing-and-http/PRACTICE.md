# Практическое задание: «Создание API-контроллера»

**Продолжительность:** 25 минут.  
**Цель:** Создать собственный изолированный API-контроллер, реализующий базовые CRUD-операции над статическим списком строк, и протестировать его работу через HTTP-файл.


## 🎨 Темы на выбор
Выберите **одну** из предложенных тем для вашего API или придумайте свой аналогичный список:
* 🎮 `GamesController` (маршрут: `api/games`) — бэклог игр, которые нужно пройти.
* ☕ `EnergyDrinksController` (маршрут: `api/energy-drinks`) — рейтинг энергетиков для выживания на сессии.
* 🧠 `MemesController` (маршрут: `api/memes`) — база названий актуальных интернет-мемов.
* 📅 `ExcusesController` (маршрут: `api/excuses`) — список отмазок, почему лабораторная сдается позже срока.

## 🚀 Пошаговый трек реализации

### 🔹 Этап 1: Уровень MVP (Minimum Viable Product)
*Цель: Настроить проект и получить первый работающий GET-запрос.*

- [ ] В папке `Controllers` текущего проекта создать новый пустой класс (например, `MemesController.cs`).
- [ ] Указать над классом обязательные атрибуты: `[ApiController]` и `[Route("api/[controller]")]`.
- [ ] Унаследовать класс контроллера от `ControllerBase`.
- [ ] Объявить внутри класса приватный **статический** список строк (`private static readonly List<string> Items = new()...`) и заполнить его 3–4 стартовыми элементами.
- [ ] Написать метод `GET`, который возвращает весь список целиком:
  ```csharp
  [HttpGet]
  public IActionResult GetAll() => Ok(Items);
  ```
- [ ] Создать в корне проекта новый файл `exercise.http`.
- [ ] Написать в нем GET-запрос к вашему новому контроллеру и успешно запустить его через Rider.

### 🔸 Этап 2: Уровень «Усложнение»
*Цель: Добавить интерактивность, фильтрацию и создание элементов.*

- [ ] Модернизировать метод `GET`: добавить в него необязательный параметр строки запроса `[FromQuery] string? search`.
- [ ] Реализовать внутри метода `GET` фильтрацию списка по совпадению подстроки (без учета регистра). Если параметр пуст — возвращать весь список.
- [ ] Написать метод `POST` для добавления нового элемента. Данные должны приниматься из тела запроса: `[FromBody] string newItem`.
- [ ] Добавить в метод `POST` валидацию: если строка пустая (`string.IsNullOrWhiteSpace`), возвращать `return BadRequest("Текст ошибки");` (статус 400).
- [ ] В файл `exercise.http` добавить два новых сценария:
  - GET-запрос с фильтром (например, `?search=тест`).
  - POST-запрос, успешно добавляющий новую строку (не забудьте обернуть строку в двойные кавычки в теле запроса!).

> [!WARNING]
> **Частая ошибка с JSON:** В теле `.http` файла текстовое значение для POST обязательно должно быть в двойных кавычках (`"Мой мем"`), иначе сервер вернет ошибку `400 Bad Request` из-за невалидного JSON.

---

### 🥷 Этап 3: Уровень «Готовый проект»
*Цель: Реализовать полное удаление и обработку исключений (полный CRUD).*

- [ ] Написать метод `DELETE`, принимающий точное название элемента через строку запроса: `[FromQuery] string name`.
- [ ] В коде метода реализовать поиск элемента в статическом списке без учета регистра.
- [ ] Если элемент **не найден** — возвращать `return NotFound("Элемент не найден");` (статус 404).
- [ ] Если элемент **найден** — удалять его из списка (`Items.RemoveAt(...)`) и возвращать `return Ok();` (статус 200).
- [ ] Дописать в файл `exercise.http` два финальных сценария для проверки удаления:
  - Успешное удаление существующего элемента.
  - Попытка удаления несуществующего элемента (проверка падения в ошибку 404).

## 🎯 Критерии успешного выполнения
1. Проект компилируется и запускается без ошибок.
2. В файле `exercise.http` настроено минимум **4 успешных сценария** (GET, GET с фильтром, POST, DELETE).
3. В файле `exercise.http` настроено минимум **2 сценария проверки ошибок** (400 Bad Request и 404 Not Found).
